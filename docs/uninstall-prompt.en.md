# ToneRelay Uninstallation Prompt

[中文](uninstall-prompt.md) | [English](uninstall-prompt.en.md)

Please completely uninstall ToneRelay's client connections, MCP service, Bridge, and Lightroom plug-in. Preserve other MCP configuration, photos, Catalogs, presets, personal data, and recoverable backups.

Read the installation manifest first, verify the actual components, their ownership, and the clients using them, and back up the relevant configuration. If shared components are still used by other clients, list the impact and ask whether to continue; continue without interruption if the same scope is already authorized. If I ask to uninstall only a specified client, remove only that client's connection. Use entry points supported by the installed version and proceed in three steps:

For macOS versions with unified configuration, first locate config.json, then read the separate install-manifest.json; a configuration backup is not another active configuration. The manifest should cover the dedicated installation root, actual data root, downloads, logs, cache/temporary directories, backups, and client configuration and Lightroom registrations outside the root. The expected root for a new macOS installation is `~/Library/Application Support/ToneRelay`, but actual locations must still be checked against records and the live system; older installations may use external data. Do not delete a development repository based on its repository name, working directory, or the installation-time `source-root`. Only installation source copies created by the installer and confirmed to belong to it may be deleted. Check the actual targets of symbolic links; external personal data and shared interpreters are excluded from deletion.

On Windows, do not copy macOS commands or assume the same manifest and process safeguards exist. Older whole-directory uninstalls delete the data inside; verify and back up personal data first, then remove software item by item rather than directly deleting the entire directory.

1. Remove ToneRelay connections from authorized clients, check unfinished jobs, and stop each client/session's MCP instances and Bridge according to identity and installation ownership. Wait for a bounded period for exit and check whether they restart; a closed port alone does not prove a process has stopped.
2. Remove Lightroom plug-in registrations or managed links. If necessary, quit Lightroom normally and reopen it. Disabling is not removal; for a symbolic link, remove only the link itself.
3. Following the manifest, delete software, installation source copies, downloads, caches, and temporary files with confirmed ownership, and clean up recorded external host connections. Confirm processes have stopped before cleanup. Preserve personal data, runtime data, and recoverable backups, and report the remaining root-directory contents and their locations. Deleting runtime data or backups requires separate explicit authorization; do not delete the entire root just to leave an empty directory. Check for remnants at old external paths. If ownership is unclear, identify the specific paths and items requiring verification rather than broadly declaring completion.

Uninstall checks only read actual client connections/tool lists, processes, registrations, and files. Do not call installation-status probes that submit Lightroom jobs again. Reconnect or create a new session only if client refresh cannot be confirmed. Stop checking once the evidence is sufficient, and mark unobservable layers as pending verification.

Uninstall without reinstalling. If “uninstall and reinstall” is explicitly requested, verify the uninstall baseline in the same task, then install from the authorized pinned source and verify read-only in a new session. Do not default to internal source for public installation. If human confirmation blocks progress, explain the action, reason, and minimum required step, save a checkpoint, and do not bypass safeguards.
