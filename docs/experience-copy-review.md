## 先定写法

这个页面面对第一次听说 ToneRelay 的人。先说他可以做什么、会看到什么，再解释 Agent、MCP、Catalog。让用户感到自己仍在决定照片的样子，而不是把判断交给一套会“自动完成一切”的系统。

- 句子短一些。一句话只讲一个动作或结果；标题不要替正文承担技术解释。
- 说清分工：**用户提出目标并看结果；Agent 判断下一步；ToneRelay 把明确操作交给 Lightroom 并返回结果。**不要把 Agent 的选片、审美判断写成 ToneRelay 的内置能力。
- 少用“赋能、闭环、多方案、精心蒸馏、真实原彩”这类需要读者自行翻译的词。必须说技术时，紧接着说明用户能看到的变化。
- 不把“减少界面截图和控件定位”直接写成未经对照测试的“更快、更省 Token”。不说“确认后才保存”：示例中的调整已经在 Lightroom 的虚拟副本上发生，用户是在看过结果后决定是否继续改。
- 画廊包是供 Agent 阅读的风格说明与参考图，不是 Lightroom 里一键套用的预设。把“网页下载、交给 Agent 使用”与“Runtime 已自动安装或读取风格包”分开；后者不能从网页有下载按钮推断出来。
- 手动调整、预设和 Agent 协作各有适用任务。页面可以比较**工作方式**，但不同照片、不同任务的截图不是同条件速度或效果对照，不必把手动操作写成错误做法。
- 真实截图中的原话、数字、照片数量要与截图一致。若另写更自然的示例提示词，就标作“可以这样说”，不要伪装成截图逐字转录。
- **不修改六张截图的像素或截图里的 Codex 对话文字。**本审稿表只讨论图片外的标题、说明、图注与替代文本；若卡片下方文字引用了真实提问，也先保持原话。可复用的起手提示词另写在 `docs/experience-card-prompts.md`，不能冒充截图实录。

建议页面层次：首屏一个标题、两句解释、一排具体能力；案例每组一个任务标题、一句引导，让截图说话；FAQ 先给普通用户可读的一句答案，技术细节随后展开。不要为填满卡片而重复同一句意思。

## 四、对比卡的复制提问

每张卡片的说明句后只放一个小的 `复制提问`，与使用引导连成一条阅读路径；编号行只保留序号和类别。01、02 直接复制；03 的同一入口展开两个选项：`主体蒙版细调` 和 `参考图调色`。第三组是两个不同任务，不应把它们硬拼成一句含糊的“万能仿色”提问。复制后提示“发给 Agent 即可开始”；复制失败沿用全站手动复制弹窗。

四段可编辑正文集中在 `docs/experience-card-prompts.md`。它们是**另写给访客使用的通用话术**，不是截图逐字稿。每段都先确认 Lightroom 中的照片或处理范围，再由用户给出审美目标，让 Agent 执行、带回预览，用户看图后继续决定。批量选片只要求 Agent 判断与调用标记工具，不写成 ToneRelay 自带模糊检测器；主体蒙版细调和参考图调色分别成段。页面仅渲染小入口，不再重复展示整段提示词。
