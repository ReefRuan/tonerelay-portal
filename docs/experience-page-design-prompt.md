# ToneRelay Portal · 立即体验页渲染设计

## 文案来源

本文件只描述页面如何呈现内容，不维护文章正文。所有面向用户的标题、段落、示例和 FAQ 统一维护在 [`experience-introduction.md`](experience-introduction.md)。

以后修改文字时，只编辑介绍 MD；不要把新文案直接写回本文件或组件代码。网页渲染器应以介绍 MD 为内容源，页面布局由本文件决定。

MCP 和工具的能力说明单独维护在 [`mcp-tools-overview.md`](mcp-tools-overview.md)，体验页只取其中适合普通访客理解的结果表达。

## 页面目标

页面像一篇可阅读的产品介绍，也像一个可以继续操作的案例画廊：先说明 ToneRelay 与 Agent、Lightroom 的关系，再展示能力、案例、开始方式和答疑。

不展示知识来源、模板蒸馏过程、Context Store、分发白名单、队列实现或内部状态。技术事实需要出现时，转译成用户能感知的结果。

## 页面结构

按文章内容顺序渲染以下区块：

1. **Agent 入口条**：文章标题、能力摘要、对比说明、推荐 Agent 和“什么是 Agent？”。
2. **开始使用**：安装提示词和 GitHub 入口。
3. **修图例子**：四个案例卡片，展示用户可以怎样提出请求。
4. **两种修图方式**：手动调整与自然语言协作的情境对比。
5. **常见照片**：人像、旅行与街头、一组照片三个场景卡片。
6. **安装提示词与 FAQ**：完整提示词和文章中的常见问题。

文章章节是内容源；区块名称是渲染目标。不要为了适配布局重写文章正文。

## Agent 入口条

入口条采用纵向结构，桌面端和窄屏端保持同一阅读顺序：

```text
标题
能力摘要
对比说明
推荐的 Agent
Agent 卡片
什么是 Agent？
```

Agent 卡片只显示文字名称。当前推荐项为 Codex、WorkBuddy、OpenClaw，不使用图标、兼容性徽章或额外英文小字。

入口条使用深色背景、蓝色边线和低对比网格，保持页面的暗色视觉基调。标题和正文优先保证阅读尺寸，不为了塞入一行而缩小文字。

## 文章区块的渲染规则

- 文章标题使用大号衬线字体；小标题负责节奏，不额外添加技术标签。
- 引用块用于用户可以直接复制给 Agent 的请求示例。
- 案例区使用四张 4:3 图片或安静的占位图；图片缺失时保留结构，不写成长技术说明。
- 对比区使用两张 16:10 图片，表达“自己慢慢试”和“说出目标、看结果”的差异。
- FAQ 保持短问短答，完整安装提示词属于 Agent 消费内容，不混入产品解释段落。
- 默认深色界面，字少、图大，案例优先于解释。

## 媒体占位

文章需要的媒体采用稳定的语义 key，文件准备好后替换资源，不修改文章结构：

| 媒体 key | 比例 | 用途 |
| --- | --- | --- |
| `feature-real-preview` | 4:3 | 一张照片的真实渲染前后效果 |
| `feature-agent-queue` | 4:3 | 参考图与旅行照片的色彩方向 |
| `feature-background-variants` | 4:3 | 一组照片统一色调 |
| `feature-measure-compare` | 4:3 | 同一夜景的多种风格测量与比较 |
| `compare-without` | 16:10 | 手动滑块与反复试调 |
| `compare-with` | 16:10 | 自然语言提出目标、查看结果、继续细调 |

## 内容与实现边界

- 文章 MD 是可独立发布的内容，不能依赖 React 组件才能读懂。
- 页面组件负责布局、按钮、复制、弹窗和媒体，不负责创造新的产品文案。
- 需要技术细节时，链接或引用 `mcp-tools-overview.md`；不要把 Runtime 内部实现直接搬进体验页。
- 不承诺未经测试的具体节省时间、Token 比例或自动化比例。
- 当前页面仍可先由组件渲染；接入 MD 渲染器时，优先保持文章章节和媒体 key 不变。
