# ToneRelay Portal · 立即体验页渲染设计

## 文案来源

本文件只描述页面如何呈现内容，不维护文章正文。所有面向用户的标题、段落、示例和 FAQ 统一维护在 [`experience-introduction.md`](experience-introduction.md)。

以后修改文字时，只编辑介绍 MD；不要把新文案直接写回本文件或组件代码。网页渲染器应以介绍 MD 为内容源，页面布局由本文件决定。

MCP 和工具的能力说明单独维护在 [`mcp-tools-overview.md`](mcp-tools-overview.md)，体验页只取其中适合普通访客理解的结果表达。

## 页面目标

页面是给第一次接触 ToneRelay 的用户看的入门介绍：先用紧凑的工具介绍说明 Agent 与 Lightroom 的分工；安装入口始终留在顶部；然后用聊天示例展示使用方式，最后答疑。

不展示知识来源、模板蒸馏过程、Context Store、分发白名单、队列实现或内部状态。技术事实需要出现时，转译成用户能感知的结果。

## 页面结构

画廊和立即体验共用相同高度、位置与字号的固定顶部导航，切换页面时“画廊 / 立即体验”不跳位。仅在立即体验显示“一键安装”“Star Portal”“Star MCP”三个操作，两个 Star 入口直接打开各自的 GitHub 仓库，用户仍须在 GitHub 登录并点击 Star；纯静态页面不代替用户写入 Star。“一键安装”复制完整安装提示词与 FAQ，提示用户发给 Agent；网页不声称已经自动装好。MCP 仓库目前私有，入口需注明这一状态，非协作者可能看到 GitHub 404。

按文章内容顺序渲染以下区块：

1. **工具介绍**：短标题、两句说明与蓝色粗体能力词；桌面端右侧紧凑展示推荐客户端和“什么是 Agent？”。
2. **对话修图示例**：直接以文章标题和引导句开场，不加“交互示意”眉题；下方依次展示对话修图、批量操作、与 Agent 直接操作界面的对比。
3. **对话答疑**：可展开的常见问题。

文章章节是内容源；区块名称是渲染目标。不要为了适配布局重写文章正文。

## Agent 入口条

入口条桌面端采用两栏，窄屏改为上下阅读：

```text
工具介绍：标题 → 简短说明 → 蓝色能力词    推荐的客户端
                                       Codex / WorkBuddy / Kimi Work
                                       什么是 Agent？
```

客户端只显示文字名称。当前推荐项为 Codex、WorkBuddy、Kimi Work，不使用图标、兼容性徽章或额外英文小字。

入口条使用深色背景和蓝色边线，保持页面的暗色视觉基调。关键词使用蓝色粗体，其他正文保持易读；不为了塞入一行而缩小文字，也不再单列大块“安装介绍”。

## 文章区块的渲染规则

- 文章标题使用大号衬线字体；小标题负责节奏，不额外添加技术标签。
- 引用块用于用户可以直接复制给 Agent 的请求示例。
- 三组交互示意各自保留左右对照；右侧是聊天界面，每个用户请求独立成一个气泡，不把多个使用场景挤进一段说明。
- 批量示例依次展示看一组照片、找出看起来模糊的照片、逐张调整选中照片、在单张照片上试多种色彩方向。Agent 可以顺序调用工具完成这些场景；示意图不暗示存在专用模糊检测器或单次调用完成整组修图。
- 与直接操控界面的对比使用“模仿参考图调色”作为同一任务：右侧先展示参考图与待修图，再由 Agent 在对话中返回两次渲染图片；每次图片下方附简短观察，体现比较后继续调整。没有同条件基准测试时不写具体节省比例或色差精度。
- FAQ 保持短问短答，完整安装提示词属于 Agent 消费内容，不混入产品解释段落。
- 默认深色界面，字少、图大，案例优先于解释。

## 媒体占位

目前的花田照片、抽象缩略图和候选色彩仅为占位。准备好真实案例后，按下列语义替换，不改对话结构：

| 媒体 key | 比例 | 用途 |
| --- | --- | --- |
| `conversation-source` | 4:3 | 一张照片及其真实 Lightroom 结果 |
| `batch-thumbnails` | 4 张缩略图 | 同组照片，包含适合人工复核的模糊案例 |
| `batch-group-results` | 多图 | 选中照片逐张调整后的结果 |
| `batch-variants` | 3 张 | 同一基准照片的多种真实渲染候选 |
| `computer-use-steps` | 16:10 | Agent 直接操作界面时的截图与控件定位示意 |
| `match-reference` | 4:3 | 用户提供的目标色调参考图 |
| `match-source` | 4:3 | 待调色的原始照片 |
| `match-round-1`、`match-round-2` | 4:3 | Agent 在对话中先后返回的两张真实 Lightroom 渲染图 |

## 内容与实现边界

- 文章 MD 是可独立发布的内容，不能依赖 React 组件才能读懂。
- 页面组件负责布局、按钮、复制、弹窗和媒体，不负责创造新的产品文案。
- 需要技术细节时，链接或引用 `mcp-tools-overview.md`；不要把 Runtime 内部实现直接搬进体验页。
- 不承诺未经测试的具体节省时间、Token 比例或自动化比例。
- 当前页面仍可先由组件渲染；接入 MD 渲染器时，优先保持文章章节和媒体 key 不变。
