# ToneRelay Portal · 立即体验页内容方向

## 目标

这一页不是技术白皮书，也不是模板生产流程说明。它要像案例画册一样，让访客在很短时间内知道两件事：

1. ToneRelay 能帮助自己把 Lightroom 照片修成什么样。
2. 想开始时，只要把安装提示词交给自己的 Agent。

参考 `awesome-gpt-image-2` 的做法：先给清晰入口和案例分类，安装放在后面。不展示知识来源、模板蒸馏过程、Context Store、分发白名单、队列实现或内部状态。

## 页面顺序

### 1. Agent 支持条

高度保持紧凑（桌面约 20vh 以内）。展示 Codex、WorkBuddy、OpenClaw 和「更多支持 MCP 的 Agent」。

- 标题：`交给你正在使用的 Agent`
- 「这是什么？」打开给新用户的说明：下载 WorkBuddy → 登录并选择模型 → 回来复制提示词。
- 不解释协议、仓库或技术架构。

### 2. 开始按钮

- 标题：`一段提示词，把安装交给 Agent。`
- 说明：`不需要先理解 MCP。把安装交给 Agent，之后直接告诉它你想要怎样的照片。`
- 主按钮：`复制安装提示词`
- 次按钮：`去 GitHub 点 Star`

### 3. 修图例子（核心内容）

用四张 4:3 图片说明用户可以提出的请求。图片未准备好时用安静的视觉占位，不能借机写成长技术说明。

| 例子 | 标题 | 一句话 | 请求示例 |
| --- | --- | --- | --- |
| 01 | 把一张照片调到位 | 说清楚想要的明暗、颜色和情绪，再从结果里继续细调。 | 保留夕阳暖意，让人物肤色自然。 |
| 02 | 跟着参考图找感觉 | 选一张喜欢的风格参考，让调整朝同一种光线和色彩关系靠近。 | 把阴天旅行照变成清爽、克制的彩色负片。 |
| 03 | 让一组照片看起来像一组 | 给同一趟旅行、婚礼或日常记录建立连贯观感。 | 统一室内、户外和混合光下的色彩倾向。 |
| 04 | 先试几种，再选一张 | 面对拿不准的照片，先比较几种方向再保留最喜欢的版本。 | 同一张夜景分别试胶片、干净数码和电影感。 |

### 4. 两种修图方式

标题：`同一张照片，两种修法。`

- 自己慢慢试：`打开照片、推拉滑块，反复比较。`
- 和 ToneRelay 一起：`说出目标、看结果，再继续细调。`

避免把传统 Lightroom 工作流写成落后的方式；只说明适用情境的差异。

### 5. 三类常见照片

保留为三个非常短的卡片：

- **人像**：肤色干净、窗边高光保留、背景不抢主体。
- **旅行与街头**：保留阴天、夜色或暖灯气氛；让不同地点的照片自然连贯。
- **一组照片**：先选方向样片，比较几种色彩关系，保留最适合整组的版本。

### 6. 安装提示词与 FAQ

完整提示词仍保留在页后，供 Agent 复制执行；它可以包含必要的安装地址和安全条件，但不作为面向人的产品介绍。

FAQ 只回答用户做决定时真正需要的问题：

- 如何描述想要的效果？
- 需要先懂 Lightroom 参数吗？
- 模板和普通预设有什么不同？
- 怎样选择模板？
- 是否会覆盖原片？
- 怎么开始安装？

## 文案和视觉原则

- 以照片、效果、情绪和具体修图请求为主语，不以 Runtime、上下文、队列或协议为主语。
- 每个功能点必须配真实效果图或简洁占位；没有图就删掉复杂论述。
- 不承诺未测试的节省时间、Token 比例或自动化能力。
- 默认深色界面，字少、图大，案例优先于解释。
