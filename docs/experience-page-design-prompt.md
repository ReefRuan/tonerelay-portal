# ToneRelay Portal · 立即体验页渲染设计

## 文案来源

本文件只描述页面如何呈现内容，不维护文章正文。体验页的主要介绍和对比卡外层文案在 [`experience-introduction.md`](experience-introduction.md)；卡片的可复制起手提问在 [`experience-card-prompts.md`](experience-card-prompts.md)；安装、卸载和答疑分别在 `install-prompt.md`、`uninstall-prompt.md`、`faq.md`。

以后修改文章文字时，编辑相应 MD，不要把新文案写回本设计说明。少量导航、按钮和弹窗短标签目前仍在组件代码里；不能笼统地说“所有文字都由一份 MD 渲染”。

MCP 和工具的能力说明单独维护在 [`mcp-tools-overview.md`](mcp-tools-overview.md)，体验页只取其中适合普通访客理解的结果表达。

## 页面目标

页面是给第一次接触 ToneRelay 的用户看的入门介绍：先用紧凑的工具介绍说明 Agent 与 Lightroom 的分工；安装入口始终留在顶部；然后用聊天示例展示使用方式，最后答疑。

不展示知识来源、模板蒸馏过程、Context Store、分发白名单、队列实现或内部状态。技术事实需要出现时，转译成用户能感知的结果。

## 页面结构

画廊和立即体验共用相同高度、位置与字号的固定顶部导航，切换页面时“画廊 / 立即体验”不跳位。仅在立即体验显示“复制安装提示词”和“Star Portal”；MCP 仓库未公开时用不可点击的状态标签说明，公开后才恢复 Star 入口。Portal 的 Star 链接打开 GitHub，访客仍须自行登录并点击 Star；纯静态页面不代替用户写入 Star，也不自动弹出 Star 提示。复制按钮提供完整安装提示词与 FAQ，提示用户发给 Agent；网页不声称已经自动装好。

按文章内容顺序渲染以下区块：

1. **工具介绍**：短标题、两句说明与蓝色粗体能力词；桌面端右侧紧凑展示推荐客户端和“什么是 Agent？”。
2. **对话修图示例**：直接以文章标题和引导句开场，不加“交互示意”眉题；先展示第一组真实操作截图，再给出三条「试着这样说」，接着展示批量操作、主体蒙版细调与参考图调色。前两组对照操作方式；第三组是两种不同任务，不当作前后实验。
3. **对话答疑**：可展开的常见问题。

文章章节是内容源；区块名称是渲染目标。不要为了适配布局重写文章正文。

## 页面美学与阅读层级

- 用深色、细网格做安静的画布；保留足够留白，让真实 Lightroom 与对话截图成为视觉主角，不再叠加装饰性图标或技术徽章。
- 体验页正文沿用全页网格背景，不额外叠加整块黑色渐变；卡片通过自身底色和边线区分内容。
- 画廊首屏尽早露出照片，体验页的第一张真实截图应先于长列提问示例出现；让网格在照片区域退后，避免背景与画面争夺注意力。
- 大号衬线标题建立文章感，正文用易读的无衬线字体，编号和少量辅助信息用等宽字。首个案例的阅读顺序是：标题 → 一句能理解的说明 → 真实操作图片 → 更多可尝试的动作。
- 蓝色留给全页导航、工具能力和安装主动作；工作流卡片的浅绿色只表达案例内部的结果与轻操作，不把每个动作都做成蓝色主按钮。
- 复制提问是“读完说明后试一试”的次级动作：紧贴说明句，保留清晰可见的下划线与键盘焦点，但视觉重量低于标题和截图。详细提示词不直接铺在卡片里。
- 安装与 Star 已有固定入口，不再用自动提示气泡遮盖导航和案例内容。

实际字体、颜色变量与网格背景在 `src/styles.css` 的 `:root` 和页面背景规则中；体验页入口条、标题及卡片样式也在同一文件。本文描述意图，代码中的样式才是当前页面的真实效果。

## Agent 入口条

入口条桌面端采用两栏，窄屏改为上下阅读：

```text
工具介绍：标题 → 简短说明 → 蓝色能力词    推荐的客户端
                                       Codex / WorkBuddy / Kimi Work
                                       什么是 Agent？
```

客户端只显示文字名称。当前推荐项为 Codex、WorkBuddy、Kimi Work，不使用图标、兼容性徽章或额外英文小字。

入口条使用深色背景和蓝色边线，保持页面的暗色视觉基调。关键词使用蓝色粗体，其他正文保持易读；不为了塞入一行而缩小文字，也不再单列大块“安装介绍”。

## 文章区块的渲染规则

- 文章标题使用大号衬线字体；小标题负责节奏，不额外添加技术标签。
- 三组卡片均用真实工作流截图，不修改截图里的 Codex 对话。图片外的标题、图注和说明另行审稿，不冒充截图原话。
- 每张卡片的 `复制提问` 紧跟说明句，和“说出想要的效果，看看照片，再接着说哪里要改。”处于同一阅读路径；编号行只标序号与类别。前两张直接复制；第三张展开“主体蒙版细调 / 参考图调色”两个选项，分别复制 `experience-card-prompts.md` 中的正文。复制失败时沿用全站的手动复制弹窗。
- 第三组是两项真实任务：上方示例突出全局参数与主体蒙版的组合，下方示例展示逐张参考图调色。截图外的“还可以接着说”是给访客的后续话术，不冒充截图里的真实对话。标题不要把整组能力缩成“修曝光”。
- 批量选片示例体现 Agent 逐张判断并调用 Lightroom 标记工具，不暗示有专用模糊检测器或单次调用完成整组修图。
- 02 的小字区分“优先读取 Lightroom 快速缩略图、可复用缓存”和“需要大图时导出 JPEG 再由 Agent 放进对话”；03 的小字说明虚拟副本的实际渲染预览会带回对话。不要把两种图片路径混写成同一种缓存或导出。
- 没有同条件基准测试时不写具体节省比例或色差精度。
- FAQ 保持短问短答，完整安装提示词属于 Agent 消费内容，不混入产品解释段落。
- 默认深色界面，字少、图大，案例优先于解释。

### 复制入口的排版与视觉

说明句是每张卡片的使用引导，复制入口应贴近句尾，让读者读完就能尝试；不要放到卡片右上角，也不要做成比标题更醒目的主按钮。保持小号、带下划线的文字动作，沿用卡片的绿色强调色；句子换行时入口自然跟随到下一行。第三张只展示一个入口，点开后再选择任务，不让两个按钮抢占标题区域。复制的正文保存在 `experience-card-prompts.md`，页面无需同时展开长提示词。

## 真实截图

前两组卡片左侧各用三张 Lightroom 截图呈现操作顺序，右侧放对应的真实对话。第三组将蒙版与仿色对话上下展示。桌面端适当加宽案例区域，避免长对话旁只留一张小图；所有截图可以点开大图，检查文字和照片细节。

来源和用途记录在 [`public/experience/SOURCES.md`](../public/experience/SOURCES.md)。截图里的 Codex 对话是实录，不作为页面文案优化对象；新增的可复制提示词是另外写给访客的起手话术。

## 内容与实现边界

- 文章 MD 是可独立发布的内容，不能依赖 React 组件才能读懂。
- 页面组件负责布局、按钮、复制、弹窗和媒体；待审稿的少量 UI 短标签仍在组件中，新增长篇文案应写入对应 MD。
- 需要技术细节时，链接或引用 `mcp-tools-overview.md`；不要把 Runtime 内部实现直接搬进体验页。
- 不承诺未经测试的具体节省时间、Token 比例或自动化比例。
- 当前页面由组件读取 MD 并渲染；改版时保留文章章节与截图的来源记录。
