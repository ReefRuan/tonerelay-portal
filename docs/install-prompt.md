# ToneRelay 安装与卸载

公开安装需要可访问、固定版本的官方发行物。当前尚未验证这样的发行物可供公众使用；下面的提示词先核对来源，再执行。不要把仓库名称、进程启动或配置写入当成安装通过。

## 安装、修复或升级：复制这一段
```text
请为我安装、修复或升级 ToneRelay for Lightroom Classic，并接入当前 Agent 客户端。

请先确认操作系统、客户端、Lightroom Classic 和已有 ToneRelay 组件。官方发行仓库候选地址是 https://github.com/ReefRuan/tonerelay-lightroom-mcp 。核对其真实身份、公开访问权限、固定发行版本和安装说明；没有可验证的公开固定版本时，明确报告公开安装尚未就绪。不要默认使用内部源码或私有仓库。本机开发源码仅在我明确指定路径并授权开发安装后使用，标记为开发版。

确认来源后，本次授权覆盖该安装所需的普通下载、依赖安装、仅 ToneRelay 配置合并、Lightroom 插件注册/启用及正常重启。沿用已有授权连续完成所有组件，不在写完配置或准备好方案后结束。保留其他 MCP 条目、照片、Catalog、预设和我的个人数据。

逐层验证并记录真实结果：
1. 按该固定版本发行说明取得安装包；官方固定版本 ZIP 也可使用，不要求先安装 Git。记录版本、来源和完整性核对结果。
2. 验证实际解释器可独立启动，所需依赖可导入，并按发行说明执行 pip check 或等价依赖检查。
3. 验证 launcher 可启动、MCP initialize 成功、工具列表与 schema 可读取。
4. 调用 Bridge 的只读健康检查，核对 Lightroom 插件实际响应，不能把 Runtime 进程启动当成插件已连接。
5. 核对 Lightroom 注册的实际插件路径、启用状态和实际加载版本；需要更新时正常退出并重开。
6. 在真实新客户端会话验证工具发现与只读调用。客户端接入只按对应产品当前官方说明操作：Codex Plugin、WorkBuddy MCP、Kimi Work 与 Kimi Code CLI 不能互相替代。

实际创建当前客户端的新会话，提交只读验证请求，检查 ToneRelay 工具是否可见、健康检查和当前选片回读是否成功。检查 Catalog 的授权身份与模式；不改照片或 Catalog，不自动重绑或关闭安全保护。进程启动与旧会话检查不能代替新会话验收。

系统密码、登录、服务条款或工具明确要求本人确认时，说明卡住的具体动作、原因与我需要完成的最小操作，并保存进度。不能创建或观察新会话时，给出可复制的只读验证请求和断点交接，标记待验证，不宣布通过。完成后列出实际证据与未验证范围。
```

## 卸载或干净重装准备：复制这一段
```text
请卸载 ToneRelay，并保留其他 MCP 配置、照片、Catalog、预设和个人数据。

先核对卸载范围、当前客户端和 ToneRelay 实际安装组件，并备份相关配置。只卸载当前客户端时仅移除它的 ToneRelay 接入；完整卸载才继续处理无人使用的共享 Runtime 和 Lightroom 插件。使用已安装版本支持的卸载方式，沿用本次授权连续完成。

分别核对客户端条目移除、Lightroom 插件禁用/注册移除、已确认归属的受管文件和进程处理；禁用不能称为文件已移除，客户端断开不能称为 Runtime 已卸载。共享组件仍被其他客户端使用或文件归属不明时保留并明确报告。移动或删除软链接只处理链接本身，保留可恢复备份。正常重启需要重启的应用，逐层报告真实结果。

实际创建客户端新会话并确认 ToneRelay 连接已移除；不能创建或观察时，说明限制、给出可复制检查请求和断点交接，标记待验证。

只要求卸载时不要重装。如果我明确要求“卸载并重装”或“干净重装验收”，请在同一任务完成卸载、新会话卸载基线核对、从本次已授权来源安装和另一个新会话的只读验证。公开安装先核对可访问的固定官方发行物；不要默认使用内部源码。真人授权卡住时，说明具体动作、原因和最小操作，保存进度；不得关闭安全保护绕过确认。
```

## 常见问题

### 现在可以公开安装吗？

当前尚未验证可供公众访问的固定官方发行物。Agent 应先核对真实仓库身份、权限和版本；验证通过后按该版本说明执行。

### 为什么还需要我确认？

普通安装步骤可连续推进。系统密码、登录或工具要求本人确认时需要你处理；Agent 应留下具体断点与最小操作。

### 什么算安装完成？

组件逐层检查通过，且真实新客户端会话发现 ToneRelay 工具并完成只读健康、Catalog 授权与当前选片检查。无法观察新会话时保留待验证状态。

### 卸载会重装吗？

只有你明确要求卸载并重装时才会在同一任务继续安装，并分别验证卸载与安装后的新会话。
