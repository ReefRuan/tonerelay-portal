# 自适应肤色与色彩忠实度 v0.7.0

## 主要意图

在当前照片和当前输出条件下，尽可能消除**有证据支持的**色彩偏差，使人物肤色自然、符合现场光，同时尽量保持背景和用户指定的风格。可以独立调用，也可以在任意风格包之后调用。它是 Agent 的判断与编辑提示词，不是可导入 Lightroom 的固定 XMP 数值。不要把不同人物、色卡近肤色块或经典摄影作品拉成同一个 RGB/Lab 目标。

## 调用时先填的输入卡

```text
照片：RAW / 已渲染；相机与 Profile；当前 Temp/Tint、曝光和裁切；输出 ICC、尺寸、渲染路径。
人物：逐人标记脸/手/颈的位置、原片和当前版；主光、反光、妆容、遮挡；可见皮肤是否足以判断。
参照：同场实体色卡型号/批次/参考文件，或同光区可信灰白物；是否有同一人的基线。
风格：无 / 有；若有，从风格包读出 2–3 个锚点（光色、背景、暗部密度等）、已用全局白平衡/分级及优先级；保留原片、风格版和保护版三个状态。
工具：本次 MCP 工具清单是否包含 trlr_native_mask；Catalog 授权、独立工作虚拟副本、可回读的局部字段与新鲜渲染；当前结果是否属于 Episode 版本。
```

缺字段就记 `unknown`。原片如果已被重度调色，只能把它当作当前输入，不能倒推出被摄者的真实肤色。读取用户已有的“按同场参照校色”或“维持创意观感”偏好；未指明时，以当前图的可追溯参照和明确风格意图决定，只有两者发生实质冲突时再提出具体选择。

## 场景路由：先判光照，再按证据选子路径

第一层判断整张图是否为混合光。若是，选 C 作为**场景编排**；按“人物 × 光区”建立子项，各子项再按 A（同光实体色卡）、B（可信中性物）、D（无参照）的优先顺序判定。若不是混合光，全图按 A、B、D 的优先顺序只选一条主路径。A 和 B 只有在同一子项证据成立时使用，不与 C 并列争夺全局白平衡；不同光区不得互借参照。

每个子项先检查人物是否可判断。若脸、颈、手的可见范围/像素不足，或皮肤主要被墨镜、发丝、重妆、反射、阴影或噪声遮住，标 `unjudged`，停止该人物的肤色校正与结论；仍可描述整体光色和背景。夜市/车内小脸可按人物分别触发这个停止条件。

| 路径 | 进入条件 | 可主张的目标 | 首选动作 |
|---|---|---|---|
| A 同场实体色卡 | 卡和人物同一光区；型号、批次、对应参考值、渲染/测量条件可追溯 | 该光区色卡再现误差及中性误差；人物仍单独看 | 先 Profile、曝光/裁切、白平衡，再按需局部修正 |
| B 可信中性参照 | 同光区灰/白物可信，无可用色卡参考值 | 中性偏差的相对改善，不能报色卡绝对色准 | 检查 Profile 与全局或本光区 Temp/Tint |
| C 混合光编排 | 不同光色真实照到人物；各区分别有或没有参照 | 每个“人物 × 光区”子项再选 A/B/D；仅有参照的子项可测其误差 | 禁止重复全局白平衡，按人/光区谨慎局部修正 |
| D 无可信参照 | 只有图像、教程或他人的肖像 | 同一人物编辑前后可读性、层次和风格保留 | 小幅观感调整，必要时停止；不声称色准提升 |

有风格时，以上每一路再加**风格约束**，不用第二个独立色准包，也不连续执行两套全局白平衡。若风格是彩色舞台光、夕阳或胶片偏色，人物可以随主光带色；处理的是无依据的综合色块、脸颈断色或人物差异被抹平。C/D 子项没有 A/B 等级参照时，不借“肤色保护”重新中和全图，只做有回退点的局部动作或保留原样。若“绝对中性”和指定风格不可兼得，报告取舍，优先保留用户明确的创作意图；只有用户要求且参照充分时才以绝对校准为目标。

## 优先局部路径：选择主体后保护肤色

背景与整体光色已有合理基线、人物整体偏色且适合整体局部调整时，优先考虑 `trlr_native_mask` 的 `subject` 蒙版。先检查当前连接的 MCP 确实列出该工具、health 与 Catalog 已授权，且现场**已有独立工作虚拟副本**或有经核实可创建这种副本的入口。当前 MCP 没有独立的通用工作副本创建工具；`trlr_native_mask` 本身也不创建副本，不能把已交付的 Episode 版本副本当作可原地改写的工作副本，也不要修改 RAW master。旧 Session 的首次写入才会附带建副本，且可能额外写显影/白平衡设置，不能默认用它为本路径准备“干净”副本。若缺少可确认的独立工作副本，就停止这条原生蒙版路径并报告前置能力缺口。原生写入也不会自动登记为新的 Episode 不可变版本。它可能切换 Lightroom 的模块与选片，写入前告知界面影响，完成后报告真实 `ui_context` 恢复结果。

1. 对工作副本 UUID 调用 `action:"inspect"`，取得最新 `expected_token`、蒙版列表与局部回读。已有适合当前人物的主体 `correction_id` 时优先复用；名称相同、只有 AI 描述符或曾经存在 ID 都不足以证明可用。没有合适主体蒙版时，使用该 token、全新的 `request_id` 调用一次 `action:"create", mask_type:"subject"`，先不附局部调色数值，保存返回的 `correction_id`。创建返回 pending、未知或回读不符时先 inspect 核验现场，不重复 create；只有 inspect 显示待计算的 AI 描述符时才考虑一次 `recompute`，它不是针对某个 correction 的精确重算。
2. 创建后核对 `catalog_applied`、真实 `segmentation_data_present`、`readback_mismatches`、全局设置及其它蒙版是否保留；几何数据存在也不代表覆盖准确。零调整的新预览通常与基线相同，**不能用它确认蒙版边界**。若 Lightroom 可显示该蒙版叠加层，请让用户核查脸、颈、手、发际、衣服、头发、近肤色物体和背景边缘；若无法看到叠加层，只能在隔离工作副本上做一次小幅可观察的局部试调，再从新渲染检查实际影响范围。无法取得这两类证据时，覆盖记为 `unknown`，不称 `coverage_verified`。`force=true` 的快速预览仍不能证明色彩新鲜度或输出 ICC；关键颜色判断按同一渲染设置取得 Lightroom 正式 JPEG 导出。`trlr_export_image` 只返回导出路径/元数据，须确认客户端能实际读取 JPEG 文件后才能声称已看图或采样；若不能读取，只报告导出事实和未完成的视觉核查。快速预览失败或异常白图按 Runtime 规则只回退导出一次，连接/Catalog 阻塞不能靠导出绕过。
3. **主体蒙版不是皮肤专用蒙版。**它可能覆盖衣服、头发和多个主体；若只需修脸、不同人物/光区应分别处理，或衣服会被明显染色，不要把整个 subject 蒙版当作肤色选区硬调。改用当前已验证能精确限制范围的路径，必要时由用户在 Lightroom 细化蒙版；无法可靠分离就保留基线并说明限制。不要自动切换到 `trlr_update_xmp_sidecar` 或 `trlr_apply_mask`：它们属于另行明确授权、针对 RAW master 的 XMP 模式。
4. 已用叠加层确认覆盖适用，或需要在隔离副本上做首次局部试调来观察范围时，再次 inspect 取**新的** token，按准确 `correction_id` 用 `action:"update"` 小步设置 `LocalTemperature`，确有绿色/品红偏差再考虑 `LocalTint`；每次写入都换新的 `request_id`。数值是 Lightroom 原生存储单位，不是 Kelvin，也没有跨照片固定的 `-0.08` 配方。背景本已合理时，不为修人物改全局 `Temperature`、`Tint`、`WhiteBalance` 或其它蒙版。每步回读局部与全局字段，查看新渲染的人物、衣服、头发、边缘和背景哨点；若试调暴露错误覆盖，停止使用该候选副本。pending/未知结果先核验，不能重放写入。

此 SDK 路径的结果先作为**独立工作副本**报告。只有另有经核实的版本化交付流程，才能称它进入新的 Episode 版本；不能把原生蒙版写入、预览或 `trlr_episode_artifact` 自身说成版本提交。保留未改基线供同图比较，若覆盖或观感不合适，停止使用该工作副本，不伪称工具提供自动回滚。

## 色卡参照怎么用

- **X-Rite ColorChecker Classic / SG**：核对 2014 年 11 月前后配方/卡片生产批次，选择匹配的官方 CGATS 参考文件；通用平均值不等于手中卡片的逐张实测值。已授权并可追溯的实际卡片读数更适合高精度要求。
- **Calibrite Passport Photo 2**：现场与人物同光拍摄；中性块、自然对象色块和创意暖化块用途分开。暖化块不能在绝对色准统计中冒充中性目标。
- **Datacolor SpyderCHECKR / 24**：核对卡片型号和数据版本；有限的“肤色”色块仅能检查色块本身的再现，不能代表人群肤色覆盖。
- 本包的 `references/` 内置了许可可追溯的**实体色卡照片**，帮助辨认 Classic 与旧款 Passport 的外观和布局；它们不是厂家标准图、CGATS/Lab 数值或人体肤色目标。旧款 Passport 照片不代表 Passport Photo 2 的版本与参考文件。采集真实卡时仍须记录同光区关系、光源、拍摄时刻、卡片批次、参考文件、相机/Profile、RAW/JPEG、输出 ICC。网页照片或后期叠放的数字色卡不能证明原场景颜色准确，也不得从包内照片像素计算色卡误差。
- 阅读本包时实际打开 [ColorChecker Classic 实体照片](references/01.jpg) 与 [旧款 ColorChecker Passport 实体照片](references/02.jpg) 看外观；逐图作者和许可见 [sources.md](sources.md)。
- 算 `ΔE00` 前使参考与测量结果采用同一 Lab 参考白点、照明体/观察者及明确的色适应与 ICC 转换；条件不明写 `not_measured`。色卡近肤色色块不设为脸部目标。

### 数字采样板：自参照肤色与背景哨点

**主要用法是“本张照片的基线数字采样板”。**对原片或风格版的每个人物分别圈粗框，按 `人-光区-脸颊/额头/颈手` 命名，再给中性物、非皮肤暖物与风格锚点各圈一框。若当前工具清单提供 `trlr_color_region_compare`，将基线和候选 Episode 已保存渲染一起输入；工具在每个粗框里优先选择低纹理、少裁切的较小采样块，并在候选版**复用同一坐标**，直接输出两版 RGB8/hex/Lab、`ΔL*a*b*` 与 `ΔE00` 变化量。默认只读紧凑数字，采样位置不确定时用 `detail=review, include_overlay=true` 看备选框和标注图；先确认选中的小块确实落在同一片皮肤或物体上，再解释结果。粗框只需大致位置，但应尽量排除眼、唇、妆容、发丝、衣物和背景；工具不做人脸/皮肤识别，画面或裁切不同则不能直接复用坐标。采样板是该照片的自参照记录，不设统一人群肤色目标，`ΔE00` 只表示变化，并非“离正确肤色还有多远”。

“数字色卡”在这里更准确地说是**同图前后数字采样板**，与拍摄时同场使用的实体色卡分开。它提高的是记录和发现异常变化的能力，不能单凭数值给出“肤色自然”判定。优先比较紧邻本次肤色编辑的基准版 → 候选版；若此前已叠加风格，基准版应是风格版，否则会把风格造成的背景变化错算到肤色保护上。每轮留出皮肤亮/中/暗格、脸颈联系格，以及背景的**蒙版边缘外侧、远离人物处、与皮肤近色的物体**三类哨点。区域数超过工具上限时分批比较。同一坐标、裁切、尺寸与 ICC 才能严肃解释数字变化。

若目标是“皮肤自然且背景尽量不动”，先看全局白平衡是否有同光区中性证据；背景和整体光色已合理而人物局部偏色时，按上面的条件优先检查原生主体蒙版。它已能在对应 Runtime/Lightroom 组合中生成真实主体分割，但不是皮肤分割，也不证明覆盖范围、边缘或跨人物适用性。未安装对应工具版本、无法准备隔离副本或选区不合适时，使用当前已验证的其它局部路径，必要时请用户在 Lightroom 细化；不能把 `readback_mismatches` 为空或零调整预览不变说成边缘正确。通过 Lightroom 蒙版叠加层或小幅局部试调后的新渲染检查整体画面及放大视图中的发际、耳朵、嘴唇、眼白、妆容、衣物、肤色相近的墙面/木头、脸颈过渡、反光和阴影。若背景哨点移动，先查蒙版外溢；若其不动，仍须看边缘及更宽的背景 ROI。

数值复核须先确认比较工具接受**实际的两张来源**。只有基线和候选都已进入受支持的已保存 Session/Episode 渲染时，才用 `trlr_color_region_compare` 查看皮肤和背景小块的 `ΔL*a*b*`/`ΔE00` 变化，再用 `trlr_image_compare(mode=aligned, roi=...)` 检查背景边缘外侧和较宽区域的像素分布；独立工作虚拟副本的 UUID、快速预览或正式导出引用不能直接当这两个工具的成对输入。尚未形成已保存版本时，取得两张同设置的 Lightroom 正式导出；若文件可供本地分析，使用已核实可处理这些文件的人工 ROI 工具按相同坐标比较，否则只报告可核实的单图数值与视觉观察，不编造成对测量。`trlr_image_compare` 是编码 RGB 通道误差，不是感知色差；重复导出的微小差异也需考虑，不设普适的 `ΔE00` 或像素阈值。最终以肤色纹理、面部体积、光色一致、脸颈手关系和整图观感判断是否自然；背景/蒙版边缘明显受损时减弱或停止使用该候选，即使肤色格数字朝预期移动也一样。

数字色卡的每格可直接写成 `RGB(红,绿,蓝)` 或 `#RRGGBB`；例如本包自制的**显示链检查格**为 `黑 #000000`、`中灰 #808080`、`白 #FFFFFF`、`红 #FF0000`、`绿 #00FF00`、`蓝 #0000FF`、`青 #00FFFF`、`品红 #FF00FF`、`黄 #FFFF00`。这些数值完全由本包定义，可由 Codex 直接读取和复算；它们只用于检查 sRGB 编码、图像传输和显示预览，不是实体 ColorChecker 的标准值、可打印校准卡或任何人的肤色真值。截图或重拍数字格后，其像素还会受显示器、相机、曝光和压缩影响。

**带色温的数字记录**按版本写 `版本/渲染哈希/输出 ICC + RAW 或已渲染 + Lightroom 白平衡回读 Temp/Tint + 人物-光区 + 中性格 RGB/Lab + 皮肤亮/中/暗格 RGB/Lab + 风格锚点`。Episode 版本的测量来源可附带 `white_balance_readback`；`reference.jpg` 是外部参考图，没有当前照片的白平衡快照。RAW `Temperature` 虽以 K 表示，仍是 Lightroom 的白平衡设置，**不是该人物所在光区实测的光源色温**；JPEG/TIFF 的 `IncrementalTemperature` 为相对滑块，不能当 K。若有真正实测的光源相关色温，还要另记测量设备、位置、时刻及色品偏移/光谱资料，并与 Lightroom 设置分栏，不相互冒充。sRGB 固定使用 D65 编码；拍摄光线和白平衡的影响已经包含在输出像素中，不能再按 K 对 `#RRGGBB` 简单乘一个暖冷系数。

常见的实体色卡“肤色”块或网上肤色十六进制色板可作**外观线索**，不能作为所有人的标准 sRGB 目标。数字比较先看同光区可信中性格与非皮肤暖物，再看该人物自己受光、中间调、阴影、颈手格的前后 `ΔL*a*b*`；中性格与肤色一起偏移时调查白平衡/Profile，只有皮肤变化时调查局部蒙版/曲线。混合光逐人物、逐光区重复；夕阳/舞台光等风格允许中性物有意带色，比较时记录这个风格目标，不把它强拉回中性。没有同场实测或同一人可信基线，就只能评价数字变化与视觉自然度，不能把数值说成真实肤色的色准误差。

已有厂商或逐张实测的色卡数据时，逐格记录 `卡片型号/批次 + 参考文件版本 + illuminant/observer + Lab 白点或 sRGB 转换条件 + 来源/许可`。若当前工具清单提供 `trlr_digital_color_references`，可把调用方提供的 sRGB8/Lab D50/Lab D65 值转成紧凑 RGB/hex 表；超出 sRGB 的值会标记裁切。再在同场色卡的受控渲染上画逐格 ROI；若提供 `trlr_color_patch_measure`，可取得该格的 sRGB8 中位数及可选 `ΔE00`。只比较同一光区、同一批次和匹配的参考条件；没有这些条件，即使工具返回了数学色差，也不能报告实体卡色准。Runtime 不内置任何未经许可核实的厂家色值。

逐像素解码和 ICC 转换由工具在本机完成，Codex 只接收最多 32 格的数字摘要；读取 `#RRGGBB` 本身几乎不耗模型上下文。对于多次精细调色，RAW/高位深工作流优先，8 位 sRGB/JPEG 只用于显示端检查和交付观察；把 JPEG 另存为 16 位或 PNG 不会补回原先丢失的信息。

## 编辑提示词：观察 → 小步修改 → 回读 → 比较

1. **划定证据和目标。**逐人看脸颊/额头的受光面、中间调、阴影、颈和手；另找同光区中性物、非皮肤暖物、背景及风格锚点。嘴唇、眼白、牙齿、妆容、镜面高光、发丝和衣物不作皮肤测量。婚纱、云/天空、湖水/浪花、车漆、玻璃反射、画框高光、扫描边框也不自动成为可信白/灰物；B 路径须知道物体材质、同光区关系和中性依据。深色皮肤尤其检查暗部体积、中间调与高光形状，不以提亮到浅肤色为目标。
2. **检查全局链路。**先看 RAW/已渲染、Profile、曝光、裁切与输出色域。只有同一可解释的偏色跨越多个同光区对象时，才尝试小幅全局白平衡或 Tint；混合光不强求唯一白点。局部反射光和有色主光先按光源解释。
3. **局部处理。**人物整体适合局部微调时先走上述 `trlr_native_mask` 主体蒙版检查与更新；只调皮肤局部或混合光分区时，须有更精确且已验证的选区。小步减轻无依据偏色或改善明度分离，保留妆容、真实红润和光线方向；检查唇、眼镜、发际线、脸颈边缘，以及同色的木头、砖、沙地和衣物是否被误改。不可可靠分离时停止该局部动作。
4. **风格约束。**独立创意调色由用户已有描述确定风格锚点；与风格包组合时从该包取得锚点及已施加的全局白平衡/分级。记录原片、风格版、加肤色保护版；任何肤色修正都要检查背景冷暖、暗部密度和暖色物。可以降低局部染色强度或仅改善人物与背景的亮度分离，不因一条肤色线把夜景刷成白天。
5. **回读与停止。**每次小步修改后回读实际参数；能实际读取新鲜 Lightroom 渲染文件时，再按同一裁切/尺寸/ICC 观察与比较；只有结果确属 Episode 版本时才用 Episode 版本语义。快速 Catalog 预览仅用于定位和粗看，关键颜色比较用可读取的正式同设置导出。若脸颈断色、遮罩色晕、衣服或头发染色、人物趋同为一种橙粉、暗部细节损失、光源方向消失或风格锚点崩溃，就减弱或停止使用该工作副本。裁切和噪声丢失的信息不能由肤色效果重建。

## 前后比较与输出格式

同图固定区域比较：每人脸部亮/中/暗区、颈/手；每个有参照的光区一处灰白/色卡；至少一处非皮肤暖物和一处风格锚点；另取蒙版边缘外侧、远处背景及近肤色非皮肤物体哨点。取得新鲜、同设置的正式 sRGB 导出后先确认能读取两份 JPEG 文件，才能记录每区 Lab 变化与通道裁切；导出元数据可单独记录文件哈希/ICC/裁切/尺寸，文件不可访问时数值与视觉结果写 `not_measured`/`unjudged`。色卡只在参考条件完整时报告逐格 `ΔE00`、中位数与较差色块；无参考写 `not_measured`。逐人皮肤 `ΔL*、Δa*、Δb*、ΔC*` 只说明变化，没有同人的测量真值就不叫准确率。视觉复审另报告面部体积、自然度、脸手联系、选区边缘、背景哨点与风格锚点。

若另有人工 ROI 比较工具，它只能报告前后 Lab/裁切变化。在已安装对应版本 Runtime 时，`trlr_color_patch_measure` 可在调用方标出的色卡格上计算 `ΔE00`，但不识别实体卡，也不验证参考文件、光照和批次。没有经过核实的匹配参考数据时，色卡误差栏必须保持 `not_measured`；不可拿皮肤 ROI 变化冒充色卡误差。

```text
路径 A/B/C/D；风格：无/锚点；证据：色卡/中性/同人基线/仅观感。
目标与实际动作：操作前值 → 回读值；影响的人物和光区。
色卡/中性：测量条件与结果，或 not_measured + 原因。
逐人皮肤：受光/中间调/阴影及颈手的变化、视觉判断、不确定性；不可判断者写 unjudged + 原因。
蒙版与交付：工作副本 UUID、subject correction_id、segmentation_data_present、覆盖视觉检查、局部/全局回读、ui_context、是否真正形成 Episode 版本；未知写 unknown。
非皮肤与风格：保留/受损的锚点、边缘副作用。
背景保护：边缘外侧/远处/近肤色物体前后变化；蒙版覆盖与外溢的可视检查；无法核查则写 unknown。
决定：保留/减弱/回退；可声称的结论和证据缺口。
```

经典人像和跨肤色样片只用于观察造型、明暗、背景和艺术家色彩意图；它们不是被摄者原肤色的校准记录。此包目前是候选内容。没有同拍有授权 RAW/实体色卡、多肤色和 Lightroom 成对评估时，不得报告“已验证提升色准”。

风格压力参照可查 [Gordon Parks 的彩色纪实作品](https://www.gordonparksfoundation.org/gordon-parks/photography-archive/segregation-story-1956/gordon-parks)、[Deana Lawson 的深肤色室内双人肖像](https://www.cartermuseum.org/collection/barbara-and-mother-p202144)和 [Rineke Dijkstra 的简洁室内肖像](https://www.metmuseum.org/art/collection/search/294427)。只看风格、空间和人物体积；不拷贝作品，不把馆藏数字图当现场色卡测量值。
